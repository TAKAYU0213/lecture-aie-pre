# preDay 2の記録

## 今日の目標

Git/GitHubとLinuxの基本操作を応用し、シェルスクリプトによる処理の自動化と、GitHub Actionsを利用したCI/CDの仕組みを理解する。

- シェルスクリプトでWebページの応答コードや確認日時を取得する。
- テンプレートからレポートを自動生成する。
- Gitのbranch、commit、push、Pull Request、mergeによる変更管理を実践する。
- GitHub Actionsで処理を自動化し、Codespacesとの実行環境の違いを確認する。

## 学んだこと

### 1. シェルスクリプトによる自動化

`pre_day2/template.md`と`pre_day2/generate.sh`を作成し、Webページの確認結果から`report.md`を自動生成した。

- `#!/bin/sh`：スクリプトを実行するプログラムを指定する。
- `set -eu`：エラーや未定義変数があった場合に処理を停止する。
- `curl`：HTTPリクエストを送信し、応答コードを取得する。
- `date -u`：UTCで日時を取得する。
- `sed`：テンプレート内の文字列を取得した値に置き換える。
- `$(...)`：コマンドの実行結果を取得する。
- `chmod +x`：ファイルに実行権限を付与する。
- `sh -n`：スクリプトを実行せずに構文を確認する。

実行時に`Permission denied`が発生したが、ファイルに実行権限がないことが原因だった。`chmod +x`で解決し、レポート生成に成功した。

### 2. Git/GitHubによる変更管理

`master`から`feature/add-machine-name`ブランチを作成し、レポートに実行マシン名を追加する変更を行った。

- `git status`：変更・未追跡ファイルを確認する。
- `git add`：コミットする変更をステージングする。
- `git commit`：変更履歴を記録する。
- `git push`：変更をGitHubへ送信する。
- `git fetch`：リモートの最新情報を取得する。
- `git merge`：異なるブランチの変更を統合する。
- `git pull --ff-only`：履歴を分岐させずにローカルブランチを更新する。
- `git diff`：ファイルの変更内容を確認する。
- `git restore`：未コミットの変更を元に戻す。

Pull Request #1で`report.md`のマージコンフリクトが発生した。

原因は、CodespacesとGitHub Actionsが同じレポートファイルを異なる内容で生成したことだった。

最新の`master`を取り込み、レポートを再生成して競合を解消した。その後、Pull Requestを`master`にマージした。

**Gitでは変更履歴を管理するだけでなく、複数の変更が競合した場合に、その内容を確認して適切に統合することが重要だと学んだ。**

### 3. GitHub Actionsによる自動化

`generate.sh setup-actions`を実行し、`.github/workflows/update-report.yml`を作成した。

GitHub Actionsによって、GitHub上の実行環境でWebページの確認レポートを自動生成し、更新結果をリポジトリに記録できた。

実際の結果は以下のとおり。

| 項目 | Codespace | GitHub Actions |
|---|---|---|
| 実行マシン | `codespaces-448fe0` | `runnervmtai0g` |
| 確認日時（UTC） | 2026-10-25 13:57:52 | 2026-10-25 14:01:45 |
| HTTP応答コード | 200 | 200 |

同じスクリプトを実行しても、実行環境によってマシン名や実行日時が異なることを確認できた。

一方、Webページへのアクセス処理とレポート生成処理は、両方の環境で成功した。

### 4. ソフトウェアエンジニアリングとしての学び

今回の演習では、以下の開発フローを実際に経験した。

**コード変更 → commit → push → Pull Request → merge → GitHub Actionsによる自動実行 → 結果の取得**

特に重要だと感じたのは、次の点である。

- ソースコードと生成された成果物は、役割を区別して管理する。
- ファイルの保存とGitへのコミットは異なる。
- 同じスクリプトでも実行環境に依存する情報は変わる。
- 自動生成ファイルは内容が変化しやすく、Gitの競合が起こりうる。
- エラーが発生した場合は、ログと差分から原因を調べる。
- 開発環境だけでなく、自動実行環境でも正しく動作することを確認する。
